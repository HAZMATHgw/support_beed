# 필요한 지지를 유지하는 희소 비드 트리

기준 소스는 `patch-22`의 `f6dba26`입니다. 이 브랜치의 ABAB 비드 다발,
속이 빈 트렁크, 세장비에 따른 굵기, 바닥 연결과 X 가새, 바닥 비드 제거 오류
수정을 유지합니다. 트렁크를 비드 한 줄로 대체하지 않습니다.

## 달라진 배치

1. 격자와 같은 오버행·최소 섬 면적 판정을 사용하고 꺼낼 수 없는 공동을 제외합니다.
2. 접점이 기둥과 충돌해 통째로 사라지지 않도록, 비드 반지름과 XY 여유가 들어가는
   영역을 먼저 계산하고 그 안에서 대표점을 선택합니다. 오목한 면과 좁은 섬도 다룹니다.
3. 접점 간격을 비드 지름과 분리합니다. 자동값은 접촉 비드 지름의 4배입니다.
   연속된 경사면의 가까운 접점은 공유하고 빈 층으로 분리된 별도 선반은 각각 지지합니다.
4. patch-22의 아래쪽 V자 병합과 베드 도달 가능 영역 탐색을 사용합니다.
   우회가 지정 각도를 넘지 않게 하고 가지 사이의 전체 연결 구간도 검사합니다.
5. 원래의 트렁크 다발과 가새를 만든 뒤 3D 충돌 정리·연결 검사를 수행합니다.
   최종 비드에서 사라진 접점은 경고와 `plan.tree_stats`로 알립니다.

`tree_stats.supported_contacts`는 선택한 접점 근처에 최종 비드가 남았는지 나타내는
기하 진단입니다. 실제 출력 하중이나 아랫면 품질을 보증하는 수치가 아닙니다.

## 0.4mm 노즐 설정

CLI와 웹의 노즐 기본값은 0.4mm, 생성 방식은 트리입니다. 기존의 비드 크기 자동 규칙은
노즐의 절반이므로 비드는 0.2mm, 자동 접점 간격은 0.8mm가 됩니다.
이 크기가 실제 장비에서 출력되는지는 슬라이서 미리보기와 소형 시험 출력으로 확인해야 합니다.
기본 Z 간격은 기존 0.3mm 규칙을 유지합니다.

```powershell
.\.venv\Scripts\pellet-support.exe model.stl --nozzle 0.4 --tree --tree-contact-spacing 0.8 --preview -1 --dump-json
.\.venv\Scripts\pellet-support-web.exe
```

| 옵션 | 자동/기본값 | 의미 |
|---|---:|---|
| `--tree-contact-spacing` | 비드 지름 × 4 | 접점 간격. 키우면 접점과 비드가 줄어듭니다. |
| `--branch-angle` | 수직 기준 25° | 가지의 최대 기울기 |
| `--branch-merge-distance` | 비드 지름 × 6 | 같은 단계에서 병합할 후보의 최대 거리 |
| `--trunk-slenderness` | 8 | 기존 보강 굵기 기준. 작을수록 굵습니다. |
| `--no-bracing` | 지정하지 않음 | 지정하면 가새 보강을 끕니다. 기본은 보강 유지입니다. |
| `--grid` / `--no-tree` | 지정하지 않음 | 기존 격자 채우기 선택 |

라이브러리의 `SupportGenParams()`는 기존 호출과의 호환성을 위해 격자 기본값을 유지합니다.
트리 API 호출에는 `tree_enabled=True`를 명시하세요.

## 계산 최적화

- 트리는 밀집 격자용 확장 영역과 비드 수 추정을 계산하지 않습니다. 격자 예상 개수가
  크다는 이유로 희소 트리를 잘못 차단하던 경로도 제거했습니다.
- 접점은 공간 해시, 가지 병합은 기존 KD 트리로 근처 후보만 검사합니다.
- 비드마다 모든 탐지 높이를 훑던 최근접 층 검색을 이진 탐색으로 바꿨습니다.
- 같은 층 범위와 반지름의 충돌 경계는 재사용합니다.
- 정확히 같은 비드 원판 격자를 최대 256개까지 캐시합니다. 반지름을 반올림하지 않아
  이전과 동일한 좌표를 반환합니다.
- 골격 깊이 계산은 루트에서 한 번 순회합니다.

미세 벽의 충돌 검사도 탐지 슬라이스를 기반으로 하므로 탐지 해상도보다 작은 형상은
근사됩니다. 마지막 원본 메쉬 거리 보정은 유지했습니다.

## 비교와 검증

같은 모델과 설정으로 이전 `patch-22`와 수정 코드를 별도 Python 프로세스에서 실행합니다.
기본 비교 모델은 12×8×7mm의 브리지와 테이블입니다. 실제 사용자 모델의 결과는 다를 수 있습니다.

```powershell
.\.venv\Scripts\python.exe examples/compare_tree_support.py --baseline ../support_beed_patch22 --nozzle 0.4 --tree-only --json docs/tree_comparison_04mm.json
.\.venv\Scripts\python.exe examples/compare_tree_support.py --baseline ../support_beed_patch22 --nozzle 2 --bead-diameter 1 --json docs/tree_comparison_1mm.json
.\.venv\Scripts\python.exe -m pytest -q
```

비교 조건은 탐지층 0.25mm, XY 여유 0.3mm, Z 간격 0.2mm, 최소 섬 면적 0.5mm²입니다.
웹의 모든 기본 설정을 그대로 사용한 벤치마크는 아닙니다. 생성 시간은
`generation_seconds`, 생성 후 별도 기하 검사까지 포함한 시간은 `seconds`입니다.
베드에 약간 눌러 앉히는 patch-22의 압착 규칙은 유지합니다.

0.4mm 노즐 / 0.2mm 비드에서의 로컬 실측:

| 모델 | patch-22 비드 | 개선 비드 | 감소 | 생성 시간(이전 → 개선) | 최종 유지 접점 |
|---|---:|---:|---:|---:|---:|
| 브리지 | 10,453 | 5,065 | 51.5% | 2.080 → 0.703초 | 100 / 100 |
| 테이블 | 12,665 | 6,342 | 49.9% | 3.000 → 0.618초 | 132 / 132 |

두 모델 모두 중복 비드 0, 비드 사슬의 베드 연결 100%, 원본 메쉬 관통 0입니다.
시간은 이 환경의 단일 실행 측정이며 실제 사용자 모델의 개선율을 보장하지 않습니다.
원시 결과: [0.4mm 노즐](tree_comparison_04mm.json), [1mm 비드](tree_comparison_1mm.json).
실제 좌표의 동일 축척 [변경 전후 비교 그림](tree_before_after.png)도 함께 제공합니다.

검증에서는 트리·웹·입력·충돌·캐시 회귀 200개와 관련 파이프라인 9개를 통과했습니다.
외부 예제 파일이 없는 1개는 건너뛰었습니다. 기존 대형 격자 전체 파이프라인 회귀는
이번 실행에서 완료하지 않았으며, 실물 출력 시험도 아직 수행하지 않았습니다.

연결 검사는 실제 비드 반경과 `z_exact`를 사용하며, 테스트의 브리지/테이블은 모두 베드로
연결되는 형상입니다. 다른 모델의 모델 위 착지나 격자 보조 솔리드는 이 지표로 평가하지 않습니다.
